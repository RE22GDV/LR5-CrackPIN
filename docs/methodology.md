# Методика експериментів

Мета стенда — перевірити правильність пошуку PIN та пояснити зміну
вартості перебору. Вимірюється локальна послідовна перевірка кандидатів
на CPU. Платформний результат Codewars підтверджено окремими скриншотами; часові експерименти виконуються локально.

## Входи та повторення

Усі кандидати — ASCII-рядки з фіксованою шириною. Для часових прогонів
1–6 цифр перевіряється кожен рядок відповідного простору, без ранньої
зупинки. Контрольний хеш отримано від повідомлення поза цифровим простором;
за випадкового збігу програма завершується помилкою, а не скорочує прогін.

Час вимірюється всередині процесу. Виключено запуск Python,
компіляцію, друк, читання файлів і побудову графіків. У цикл входять
форматування числа, ASCII-кодування, MD5, hex-перетворення та порівняння.
Застосовано стандартну бібліотеку hashlib.
Усі три повтори збережено, основний показник — медіана.

Прогрівання MD5 здійснюється перед вимірюванням. Воно не гарантує
ідентичного стану кешів, частот CPU чи фонового навантаження.
Для коротких прогонів 10–1000 кандидатів відносний розкид може бути великим.
Ці результати не обґрунтовують універсальної оцінки продуктивності MD5.

Випадкові контрольні PIN обираються генератором random.Random із seed 5005.
Незмінність seed відтворює входи, але не часові значення.

## Сім дослідницьких питань

| Питання | Метод | Що є вимірюванням |
|---|---|---|
| Як впливає довжина | повні цикли для 1–6 цифр | час кожного з трьох повторів |
| Як впливає позиція | вісім PIN, числовий порядок | спроби й час бібліотечного пошуку |
| Як впливає хеш | MD5, SHA-256, PBKDF2-HMAC-SHA256 | час пакета та перевірок/с |
| Чи окупається таблиця | 100 000 записів і 2000 пошуків | побудова, пакетний пошук, розмір об’єктів |
| Що робить сіль | десять чотиризначних PIN | точна кількість хешувань і час |
| Як змінюються біти виходу | 1000 пар сусідніх PIN | розподіл відстаней Геммінга |
| Що змінює нерівномірність | заданий синтетичний розподіл | точний аналітичний розрахунок, не часовий замір |

Рисунок бюджету атаки — додаткова модель алфавітів розміру 10, 26 та 62.
Він використовує спільну локальну швидкість, щоб ізолювати вплив розміру
простору. Перебір буквено-цифрових паролів у роботі не вимірювався.

## Розмежування вимірювань та оцінок

Швидкість для екстраполяції довжини визначено з прямого Python-циклу
на 100 000 кандидатів. Повні простори 7–12 цифр не перебираються.
Модель припускає сталу швидкість перевірки та відсутність розпаралелювання.
Час форматування й хешування довшого рядка може змінюватися.

У порівнянні хешів викликається спільний бібліотечний інтерфейс із
перевіркою PIN та префіксом солі. Його накладні витрати відрізняються
від мінімального kata-циклу. MD5 і SHA-256 вимірюються на 50 000
кандидатах за повтор, PBKDF2 — на 200. Для PBKDF2 задано SHA-256,
20 000 ітерацій, сіль account-A та стандартну довжину 32 байти.
Параметри обрано для короткого досліду, не для рекомендації захисту.

## Таблиця та пам’ять

Таблиця містить усі MD5 п’ятизначного PIN. Якщо хеш дублюється,
побудова відмовляє: попередній PIN не перезаписується мовчки.
Окремий тест обходить простір незалежним itertools.product.

Облікований розмір — sys.getsizeof(dict) плюс розміри ключів і значень.
Не вимірюються RSS, накладні витрати алокатора, інтерпретатора та ОС.
Сам словник не зберігається у GitHub: його відтворює build_table().

Точка амортизації обчислюється як час побудови, поділений на різницю
середнього часу окремого перебору та середнього часу пошуку одного хешу.
Середнє перебору взято за 20 збереженими випадковими PIN, пошук у таблиці —
за медіаною трьох пакетів по 2000 вже підготовлених хешів. Час утворення
хешів-запитів у пакет не входить. Графік сумарної вартості є моделлю
амортизації цих вимірювань, а не окремим заміром для кожної кількості запитів.

## Сіль і дифузія

Модель MD5(salt || PIN) із різною відомою сіллю для кожного запису
ізолює повторне використання хешувань. У спільному несоленому проході
кожен кандидат порівнюється з множиною десяти цільових хешів. За солі
кожна ціль перебирається окремо. Набір PIN заданий, тому коефіцієнт
витрат у цьому досліді не є середнім для випадкової бази користувачів.

Дифузію оцінено відстанню Геммінга між виходами MD5 від сусідніх
десяткових рядків. У переходах на кшталт 00999 → 01000 може змінюватися
кілька символів, тому дослід не тестує строгий лавинний критерій
«один змінений біт входу». Середнє біля половини виходу не є доказом безпеки.

## Синтетичний розподіл

Імовірності 0,2 для 00000 та 0,1 для 12345 задано вручну. Інші PIN
мають однакові ймовірності 0,7 / 99 998. Обчислено ентропію, середню
кількість спроб і шанс успіху за обмеженого бюджету. Оптимальний порядок
починається з двох найбільш імовірних PIN. Усі криві отримано точним
підсумовуванням заданих імовірностей; випадкова вибірка не потрібна.

## Аудит тверджень

Первинні часові дані, вхідні PIN, кількість кандидатів, параметри
алгоритмів, seed, час UTC, версію Python та ОС містяться в
experiments.json. test_results.py повторно обчислює медіани, швидкості,
екстраполяції, амортизацію, лічильники сольової атаки й середню дифузію.

Повторний запуск оновлює JSON, summary.md і графіки. README та локальний
звіт є описом конкретного зафіксованого прогону; при зміні первинних
вимірювань їхні числа треба узгодити. Колізії MD5 поза цифровою множиною,
мережеві атаки й реальні розподіли людських паролів тут не досліджуються.
Додаткові реальні CPU/GPU-досліди описано окремо в hardware_methodology.md;
їхні первинні дані зберігаються в hardware.json та gpu.json.
